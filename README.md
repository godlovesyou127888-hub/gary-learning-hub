# Gary Learning Hub

Gary Learning Hub 是所有學習網站的中央母站。

## 原則

- 所有新網站先加入這個 Hub。
- 各子網站只保留「回 Gary Learning Hub」與「聯絡站長」。
- 不再在每個子網站重複維護完整網站群組。
- 更新採小批次、人工審核優先。

## 目前內容

- 樂齡英語
- TOEIC / 英語檢定
- 文法與單字
- 學科複習
- AI 工具
- 雙語品格教育

## 維護流程

Gary 提出新增或修改需求 → ChatGPT 修改 repository → 自動部署服務更新公開網站。

> Repository 暫時使用既有空白 repo `hi` 初始化。待 GitHub 端將名稱改為 `gary-learning-hub` 後，即作為正式母站。


## 診斷網站雙交付規則

所有診斷、評估、雷達型網站上線前都必須符合：
1. 填寫人輸入姓名與有效 Email。
2. 完成後可在畫面查看結果。
3. 填寫人收到自己的完整結果副本。
4. Gary 教練同步收到同一份診斷摘要與基本資料。
5. 填寫人可另存 PDF，研究／分析型工具另提供 CSV。
6. 郵件送達與畫面顯示分開驗證；不能把「已顯示結果」視為「Email 已送達」。
7. 未通過雙交付測試的診斷站不得標示為正式上線。


## GitHub 安全寫入與部署規則

為避免大型單次寫入被安全檢查誤擋，所有新網站與重大改版固定採用分段提交：

1. **Shell**：先建立最小可用頁面與正式路徑，確認不會 `Not Found`。
2. **Core**：加入核心診斷／練習／計算功能，不同時塞入郵寄與大量資料。
3. **Delivery**：再加入學生＋教練雙交付、PDF／CSV、FormSubmit 等交付功能。
4. **Sync**：最後才更新 Hub 與 Roadmap 的狀態＋網址，讓統計自動重算。
5. **Verify**：每一段 commit 後都先確認 Render deployment 狀態；只有 `live` 才可對外宣稱已上線。

額外規則：
- 避免一次提交超長 HTML＋大量題庫＋表單郵寄＋Hub／Roadmap 同步。
- 若單次 `create_file` 或 `update_file` 被安全檢查擋下，立即拆分，不重複提交同一大包內容。
- 先確保路徑存在，再補功能；這可避免使用者先看到 `Not Found`。
- Hub 與 Roadmap 不手動維護總數，僅更新資料列，統計由頁面自動計算。
